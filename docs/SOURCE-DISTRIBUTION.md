# Diagnostic corresponding-source package

A diagnostic ELF handed to another person must be accompanied by the actual
corresponding source and retained license notices. A GitHub link alone does not
supply that package. This packaging workflow is for the reviewed
`minimal-syscall-v6` diagnostic and independently selected capture, codec and
control-only application candidates. The production transport remains Unsupported;
packaging establishes no PS5, firmware, loader, controller or audio compatibility
and is not a release.

After the intended project changes are committed, rebuild the ELF from the clean
commit using the pinned toolchain described in [TOOLCHAIN.md](TOOLCHAIN.md).
Keep the resulting ELF, manifest and Rust archive locally. Then run:

```sh
python3 tools/package_source.py
```

The offline command writes `build/ps5/ps5-bt-source.tar.gz`. It uses the ten hash-verified
already available SDK inputs in `.sdk/a7685ce8e97ce1f8a4f38253a41d54241c9124f1/`,
or the same `PS5_SDK_SOURCE` directory used for the build. It never fetches files.
For a separately built optional diagnostic, select its manifest explicitly:

```sh
python3 tools/package_source.py --manifest build/ps5/ps5-bt-native-query.manifest.json
python3 tools/package_source.py --manifest build/ps5/ps5-bt-usb-metadata.manifest.json
python3 tools/package_source.py --manifest build/ps5/ps5-bt-capture-preflight.manifest.json
python3 tools/package_source.py --manifest build/ps5/ps5-bt-capture-once.manifest.json
python3 tools/package_source.py --manifest build/ps5/ps5-bt-sbc-selftest.manifest.json
python3 tools/package_source.py --manifest build/ps5/ps5-bt-application-control.manifest.json
```

Each writes its corresponding `build/ps5/<artifact-stem>-source.tar.gz`, binds
the package to that exact stem's ELF, and supplies an explicit rebuild command
retaining the selected diagnostic flag and loader-kernel-resolver flag from
the manifest. Diagnostic selections are mutually exclusive and must be booleans.
Capture variants require the existing-loader kernel resolver, matching their
builder contract. Including a capture diagnostic in this packaging workflow
is not evidence that capture opened or read PCM successfully.
The SBC self-test package additionally verifies and includes the complete
replacement-link bundle generated by the target codec builder. This is a
generated-signal codec diagnostic, not Bluetooth, capture or audible playback.
The default command remains bound to `ps5-bt.elf`. Run
`python3 tools/package_source.py --self-test` for synthetic packaging tests.

Packaging requires a clean Git worktree, including no untracked project files,
and the same clean Git HEAD recorded in the build manifest. It verifies the ELF
and Rust archive SHA-256, linked project source hashes, runtime review hash, SDK
revision and all selected SDK source hashes against the builder's pinned
inventory. The USB variant also requires `sdk_headers` to equal the exact
relative-path/hash map in `tools/usb_sdk_headers.json`, currently 34 headers,
and verifies all those original files locally before bundling them. Missing,
modified, extra or absolute/escaping manifest header paths fail; only the
reviewed pinned map drives filesystem reads. No SDK Git checkout is required
for a bundled rebuild: original selected file hashes establish source identity.
A dirty or stale build fails; the previous source package is removed
before validation, so a failure cannot leave a stale package as apparent output.
Commit changes and rebuild instead of editing a manifest to bypass these checks.

The complete project source contains the pristine selected libsbc source, its
LGPL text/notices, three local patches and rebuild tests. For either SBC diagnostic
variant, packaging requires `codec_sources` to be the exact path/hash map
returned by `tools/target_sbc.py`, verifies the built codec archive hash, and
requires the exact selected `build/ps5/ps5-bt-sbc-selftest-relink/` or
`build/ps5/ps5-bt-sbc-continuous-relink/` inventory. Missing,
extra, modified, escaping or symlinked relink inputs fail closed. Other variants
reject codec-only manifest fields.

The archive contains:

- `ps5-bt-source/project/`: every tracked file from the clean project commit,
  including Rust/C/assembly sources, headers, tests, build/inspection/packaging
  scripts, toolchain configuration, lock files, documentation and GPL text in
  `LICENSE`. Tracked file modes are retained; ignored and untracked files are
  excluded. Tracked files matching ignore rules, symlinks and submodules fail
  explicitly rather than silently including artifacts or losing source.
- `ps5-bt-source/sdk/a7685ce8e97ce1f8a4f38253a41d54241c9124f1/`: the ten
  files pinned by tools/build_ps5.py (syscall subset and optional kernel-resolver
  sources/headers), with their original bytes
  and John Törnblom's copyright, GPL-3.0-or-later and warranty notices intact.
  No local SDK patches are applied. See [UPSTREAM.md](UPSTREAM.md).
  The USB metadata variant additionally includes the exact pinned SDK header
  dependency closure, including `sys/dirent.h`, `sys/syscall.h` and the USB
  descriptor/ioctl headers. Their original bytes and file-specific BSD and other
  copyright, license and disclaimer notices remain intact. The root GPL text
  does not replace those terms. Default, native-query and capture packages do
  not include these additional SDK headers. The application-control variant
  independently includes its exact 43-header target POSIX dependency closure from
  `tools/application_sdk_headers.json`, retaining every original notice and the
  expanded original bytes of upstream errno/fcntl/stdint header links.
- `ps5-bt-source/build-manifest.json`: the original ELF build record, including
  its SHA-256 and the original clean project commit. The standalone associated
  ELF, compiler tools, SDK binaries, console files and Git history are not
  bundled. Each SBC diagnostic's `relink/` subtree deliberately contains a
  baseline ELF copy and the Rust archive as replacement-link evidence.
- `ps5-bt-source/README.source.txt`: concrete rebuild commands using the bundled
  selected SDK tree through `PS5_SDK_SOURCE`, Rust 1.90.0 and LLVM 18.1.8.
- For either SBC diagnostic, `ps5-bt-source/relink/`: ordered application
  objects, the Rust archive, linker script, inspection helper, exact library
  source/patch inputs, the default separately linked codec archive and
  `relink.py`. The default baseline ELF and its link map, structural report,
  inspection, disassembly and result record prove that the supplied materials
  reproduce the associated ELF. `relink.py --codec <replacement archive>`
  verifies every immutable input and emits the same bounded evidence for a
  rebuilt or modified compatible codec archive. The default codec is
  intentionally replaceable rather than listed as immutable.

The extracted project has no `.git` directory. Its README explicitly creates a
new local Git snapshot because the builder records Git provenance. That local
commit differs from the original build commit; the included original manifest
remains the record for the associated ELF. A rebuilt ELF receives its own
manifest. Install the documented external tools and Rust target before an offline
rebuild. The project has no third-party Cargo registry dependencies. Tools are
not included. A second macOS arm64 machine reproduced the baseline ELF hash
recorded in [WAVE-1-REPORT.md](WAVE-1-REPORT.md); byte-identical output on other
hosts is not claimed.

Tar member ordering, ownership, timestamps and gzip timestamp/name are normalized;
repeating packaging for identical committed source, SDK bytes and manifest must
produce the same package bytes. This is package determinism, not proof of runtime
correctness or cross-host compiler reproducibility. Review staged project content
before committing: packaging includes every tracked file and cannot decide
whether a newly committed file contains a secret or inappropriate material.

Distribute the source package together with the matching ELF and its original
manifest; identify both hashes. Retain the package and exact build provenance
for any subsequent distribution obligations. The root GPL text does not replace
file-specific terms. This is a technical source-delivery mechanism, not a final
legal determination of every possible distribution arrangement.

The build requires no Sony binary, firmware, key, exploit, SDK stock CRT or
bundled loader. The explicit HW-1 variant includes the audited SDK kernel
resolver described in RUNTIME-REVIEW.md. Existing permission and
compatible-loader prerequisites and actual loader behavior remain external. The
repaired diagnostic runtime reached Rust and final expected Unsupported on the
recorded Slim/13.40 environment; that does not establish USB/capture behavior.
See [HW1-REPAIR.md](HW1-REPAIR.md), [RUNTIME-REVIEW.md](RUNTIME-REVIEW.md)
and [HARDWARE-TEST.md](HARDWARE-TEST.md). There is no project installation bypass
or console deployment procedure. If a distribution arrangement requires further
installation information, resolve that obligation for its actual environment
before distribution; the package does not claim an exemption or supply unknown
firmware-specific facts.

The packaging self-test uses synthetic SDK/header/relink fixtures and real
temporary Git repositories. It verifies deterministic archives and exact
contents/rebuild flags for every supported diagnostic selection; retained original
header bytes; the exact codec source and immutable relink maps; replacement
codec/Rust archive/baseline ELF identity; missing/modified relink rejection;
missing variant-source rejection; boolean/exclusivity rules; capture resolver
gates; missing/modified header files and pins; path escapes; and removal of
stale outputs after failure. It never downloads sources, executes target
payloads or accesses a PS5.

## New Rust diagnostic identities

The independent `--capture-stream`, `--sbc-continuous` and `--application-control`
builds use the same clean-commit workflow. Their manifests must additionally record
a valid embedded build identity and matching candidate stem. All three source bundles
include all tracked capture/clock/runner sources; the continuous SBC bundle also
includes its exact LGPL source and executable replacement-link materials.
The seven-item kit includes all three alongside the original four candidates. Generated outcomes
and raw hardware logs remain external evidence, not corresponding source.
See DIAGNOSTIC-RESULTS.md for bounded local outcome collection.


## Control-only application source selection

`--application-control` packaging requires the exact matching candidate stem,
embedded build identity, Rust archive, factory/startup/service sources, selected
POSIX bridge/redirect headers and original SDK header map. It preserves the explicit
`--application-control --loader-kernel-resolver` rebuild command. Target header
identity is separate from USB metadata selection: missing, changed, extra or
escaping `sdk_headers` entries fail before packaging. The original 43-header
inventory retains its distinct BSD/USL/Barcroft/WIDE/NetBSD/FreeBSD Foundation and
advertising-clause notices. No SDK header is modified or replaced by host layouts.

This artifact links the reviewed protected store/listener/clock and Rust control-only
assembly, performs no radio/capture/codec operation and requires no codec archive or
replacement-link subtree. The complete tracked source still retains the existing
codec sources/notices for other independently selected variants. Its package is
reviewable source delivery, not a native import/entropy/filesystem/scheduling result.
An existing private 0700 directory, ephemeral loopback policy and fresh unlogged
authorization are runtime prerequisites; none is provisioned, deployed or inferred
by packaging. Existing capture/SBC diagnostic bounds and replacement obligations
remain unchanged. See APPLICATION-STARTUP.md and PS5-POSIX-IMPORTS.md.
